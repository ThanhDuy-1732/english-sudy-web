## Task 1: Gemini Library Fixes

**Files:**
- Modify: `src/lib/gemini.ts`
- Modify: `src/lib/__tests__/gemini.test.ts`

**Bugs to fix:**

### Bug 1a — JSON.parse without try/catch (line 28)
`generateWords` calls `JSON.parse(text)` with no error handling. If Gemini returns malformed JSON (e.g. prepended prose, safety block, empty string), this throws an uncaught `SyntaxError` that propagates through the entire call chain.

**Fix:** Wrap `JSON.parse` in try/catch; throw a descriptive `Error` instead:
```ts
let parsed: GeneratedWord[];
try {
  parsed = JSON.parse(text) as GeneratedWord[];
} catch {
  throw new Error(`Gemini returned invalid JSON: ${text.slice(0, 100)}`);
}
return parsed;
```

### Bug 1b — Case-sensitive code fence regex (line 20)
`stripJsonCodeFence` uses `/^```[a-z]*\n?/` which does not match `` ```JSON `` (uppercase). When Gemini wraps JSON in an uppercase fence, the fence is not stripped and `JSON.parse` receives the raw backticks.

**Fix:** Add `i` flag to both regexes:
```ts
function stripJsonCodeFence(text: string) {
  return text.trim().replace(/^```[a-z]*\n?/i, "").replace(/\n?```$/i, "");
}
```

### Bug 1c — New Gemini client instantiated on every request (line 9)
`getModel()` creates a new `GoogleGenerativeAI` instance and calls `getGenerativeModel()` on every API request. These are stateless config objects — they should be built once.

**Fix:** Move client initialization to module level:
```ts
function getModel() {
  const apiKey = process.env.GEMINI_API_KEY;
  if (!apiKey) {
    throw new Error("GEMINI_API_KEY is not configured");
  }
  const genAI = new GoogleGenerativeAI(apiKey);
  return genAI.getGenerativeModel({ model: "gemini-1.5-flash" });
}
```
**Note:** Keep the env-var check inside the function (it runs server-side per-request) — only extract if the pattern is clearly module-safe. If keeping it per-call is simpler, that is acceptable; the priority is bugs 1a and 1b.

**Tests to update:**
- `src/lib/__tests__/gemini.test.ts`: Add a test for malformed JSON from `generateWords` — it should throw a descriptive error, not an opaque `SyntaxError`.
- Verify the existing tests still pass after changes.

**Bugs to fix:**

### Bug 2a — No try/catch in generate-words route (line 11)
Any throw from `generateWords()` (API error, JSON parse error from Bug 1a, missing key) escapes the route handler. Next.js returns an HTML 500 page instead of a JSON error body. Clients can catch `!res.ok` but the server logs nothing structured.

**Fix:**
```ts
export async function POST(req: NextRequest) {
  const { topic } = (await req.json()) as { topic?: string };
  if (!topic) {
    return NextResponse.json({ error: "topic is required" }, { status: 400 });
  }
  try {
    const words = await generateWords(topic);
    return NextResponse.json(words);
  } catch (error) {
    const message = error instanceof Error ? error.message : "Unknown error";
    return NextResponse.json({ error: message }, { status: 500 });
  }
}
```

### Bug 2b — No try/catch in generate-sentence route (line 11)
Same problem as Bug 2a, for `generateSentence`.

**Fix:** Apply the same try/catch pattern as Bug 2a.

**Tests to update:**

## Task 3: Flashcard Component Bugs

**Files:**
- Modify: `src/components/Flashcard.tsx`
- Modify: `src/components/__tests__/Flashcard.test.tsx`

**Bugs to fix:**

### Bug 3a — setFlipped runs unconditionally during in-flight fetch (line 44)
`setFlipped((current) => !current)` executes at the end of `handleFlip` regardless of whether a fetch is in progress. If the user clicks the card while loading (to flip back), the card flips to front. When the fetch then resolves, `setExample` is called but `flipped` is false — the sentence is silently stored but never shown. The user must click a third time.

**Fix:** Move `setFlipped` inside the if block (fetch branch) so it does NOT fire on clicks that only toggle an already-visible back face. For non-fetch clicks (flipped=true, or example already loaded), `setFlipped` should still toggle:

```tsx
async function handleFlip() {
  if (!flipped && !example && !loading) {
    setLoading(true);
    setError(null);
    try {
      const res = await fetch("/api/generate-sentence", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ word }),
      });
      if (!res.ok) {
        throw new Error();
      }
      const data = (await res.json()) as { sentence: string };
      setExample(data.sentence);
      setFlipped(true);   // ← flip AFTER fetch succeeds
    } catch {
      setError("Không thể tạo câu ví dụ.");
    } finally {
      setLoading(false);
    }
  } else if (!loading) {
    // Only toggle when not mid-fetch
    setFlipped((current) => !current);
  }
}
```

### Bug 3b — setSaved(true) fires even when saveLearnedWord silently no-ops (line 58)
`saveLearnedWord` returns `void` and silently skips duplicate words. `handleSave` calls `setSaved(true)` unconditionally after, showing "Đã lưu ✓" as false feedback when the word already exists.

**Fix:** Change `saveLearnedWord` return type to `boolean` and check it before `setSaved`:

In `src/lib/storage.ts`:
```ts
export function saveLearnedWord(entry: LearnedWord): boolean {
  const words = getLearnedWords();
  if (words.some((word) => word.word === entry.word)) return false;
  localStorage.setItem(KEY, JSON.stringify([...words, entry]));
  return true;
}
```

In `src/components/Flashcard.tsx`:
```tsx
function handleSave(event: React.MouseEvent<HTMLButtonElement>) {
  event.stopPropagation();
  if (!example) return;
  const didSave = saveLearnedWord({ word, meaning, example, topic, learnedAt: new Date().toISOString() });
  if (didSave) setSaved(true);
}
```

### Bug 3c — Dead error message string in throw (line 29)
`throw new Error("Failed to generate sentence")` — the `catch {}` block never reads the thrown error; it always uses a hardcoded Vietnamese string. The message allocation is wasted.

**Fix:** Replace `throw new Error("Failed to generate sentence")` with `throw new Error()` (no message). The catch block is unchanged.

- Add a test: when `saveLearnedWord` returns false (already saved), `setSaved` should NOT be set to true.
- Update the existing save test to account for the new return value.
- Update any storage tests that check `saveLearnedWord` return type.

**Bugs to fix:**

### Bug 4a — Case-sensitive duplicate check (storage.ts line 27)
`words.some((word) => word.word === entry.word)` is case-sensitive. Gemini can return "Negotiate" one session and "negotiate" another — both pass the check and are saved as separate entries.

**Fix:** Lowercase both sides:
```ts
if (words.some((w) => w.word.toLowerCase() === entry.word.toLowerCase())) return false;
```

### Bug 4b — Double localStorage read in handleDelete (history/page.tsx line 19)
`handleDelete` calls `deleteLearnedWord` (which reads and writes localStorage) and then calls `getLearnedWords()` again to refresh state. The second read is unnecessary — the result is derivable from in-memory state.

**Fix:**
```tsx
function handleDelete(word: string) {
  deleteLearnedWord(word);
  const nextWords = words.filter((w) => w.word !== word);
  setWords(nextWords);
  if (filter !== "Tất cả" && !nextWords.some((entry) => entry.topic === filter)) {
    setFilter("Tất cả");
  }
}
```
